Case 01 / Platform Workflow Strategy

Project Setup & Workflow Strategy

Principal UX Designer | Core Platform | 2023-Present

I reframed a fragmented project setup process into a clearer self-service workflow, helping technical users understand what to do, who owned each step, and where supporting documentation lived.

User Problem

Teams could not confidently create or set up projects without asking for help, because the workflow crossed tools, teams, permissions, and documentation.

Design Goal

Make setup feel guided and independent: clear steps, visible dependencies, and support content available at the moment of need.

Problem

The board showed a recurring setup pain: project teams were trying to complete a workflow that had grown through organizational history rather than user logic. Required actions lived across disconnected tools, instructions were scattered, and the user often had to ask a platform specialist what came next.

The real UX issue was not only interface complexity. It was an unclear operating model: users needed a path, dependencies, decision points, and confidence that they had completed the right steps.

Approach

Mapped the full setup journey

I worked from user tasks rather than system boundaries, documenting each step from project creation through configuration, permissions, and handoff.

Identified repeated blockers

I grouped common challenges into patterns: missing prerequisites, unclear ownership, duplicated instructions, and support-only knowledge.

Designed a guided flow

The proposed flow made sequence and status visible, reducing the need for users to infer what the platform expected from them.

Connected documentation to action

Instead of pushing users to a separate knowledge base, the design brought short, relevant guidance into the workflow.

Design decisions

1. Structure the workflow around user intent

Users did not think in terms of backend systems. The flow was organized around the outcome they were trying to complete: creating and preparing a project for real work.

2. Make dependencies visible

Setup tasks often failed because users did not know a previous condition was missing. The design surfaced prerequisites and completion states earlier.

3. Use documentation as product surface

Support content became part of the experience, not a separate rescue path. This reduced reliance on platform specialists and made the workflow more teachable.

The target experience: users can create or set up a project in minutes, move independently through the flow, and get clear support at each step.

Impact

  • Turned an unclear setup journey into a productized workflow that could be discussed, prioritized, and improved.
  • Created shared language across PM, engineering, and support teams around the exact points where users were blocked.
  • Established a repeatable pattern for turning internal platform procedures into guided self-service experiences.
